* How can I ensure that my code, program, or software is functional and secure?
  * To ensure that a program is functional, extensive testing is required. This is not the only way, as a program that passes tests does not necesssarily mean that it is functional. A program also needs to meet the users needs, which are interpreted into requirements for the software. Sticking close, and frequently referencing the software's requirements is an important part of the software development life cycle, and will help to prevent tech debt.
* How do I interpret user needs and incorporate them into a program?
  * Taking a statement such as "I need to be able to keep records of people, their appointment dates and what needs to be done" and intepreting it into code is a lengthy task. The user tells you what it is they want or need, and you have to infer what additional support a piece of software needs to accomplish that goal. It is one thing to be able to take in a bunch of strings and store them in an object, but how easily accessible is that data after that? How does that data relate to all the rest of the data, and what kind of user interface will be sufficient for the users needs. Answering questions like this lead down a path of discovery, but it's also important not to make too many assumptions. Checking in with users and stake holders is a must so that bounds are not overstepped, and nothing gets forgotten or neglected.
* How do I approach designing software?
  * I start by mapping out the most basic requirements. I need to accept input here, it needs to go there, and then this needs to come back. Once I have the skeleton of what is needed, I can then add in the rest of the little bits and pieces that make the program work, like figuring out what the best data structures for this use case are, how I can write code in a way that could be easily understood and potentially reused. What parts can be written with the express purpose of being reused by utilizing Object Oriented Programming methods.
